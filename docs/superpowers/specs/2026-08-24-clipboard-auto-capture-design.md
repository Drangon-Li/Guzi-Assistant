# 剪贴板自动捕获

> 设计文档（spec）。面向实施。日期 2026-08-24。
> 用户复制到疑似日程的内容时主动提示，替代「必须记得按 Alt+C」。Alt+C 保留为手动兜底。

## 1. 背景与目标

现有剪贴板捕获必须用户主动按 Alt+C（`hotkey.ts` → `capture.ts:readClipboardPending`）。用户提出改为自动感知。

剪贴板是全机最敏感的缓冲区——密码、2FA、API key 都从这里过，而本应用会把文本送云端解析。
所以本设计的第一约束不是「识别得准」，而是**绝大多数复制根本不被读取**。

**目标**：复制到疑似日程 → 桌宠气泡 + 检测卡确认。
**非目标**：不动 Alt+C（保留，含图片/文件路径）；不做图片/文件的自动捕获；不改屏幕感知。

## 2. 关键调研结论（均在 macOS 26.5 真机实测）

### 2.1 macOS 原生提供了正好需要的算法

`NSPasteboard` 在 macOS 15.4+ 提供 `detectPatternsForPatterns:completionHandler:`。SDK 头文件原文：

> Determines whether the first pasteboard item matches the specified patterns, **without notifying the person using the app**. This method... **doesn't allow the app to access the item's contents**.

模式集里有 `NSPasteboardDetectionPatternCalendarEvent`。实测（`AppKit.framework/Headers/NSPasteboard.h` 为准）：

| 剪贴板内容 | detectPatterns 结果 |
|---|---|
| 明天下午三点开组会 | CalendarEvent |
| 周五前把修改后的论文发给张磊老师 | CalendarEvent |
| 8月28日 14:30 在腾讯会议开中期答辩 | CalendarEvent, Number |
| 记得下周三交实验报告 | CalendarEvent |
| Meeting tomorrow at 3pm in Room 401 | CalendarEvent |
| `sk-proj-AbCdEf0123...` | （无） |
| `const x = arr.map(v => v * 2)` | （无） |
| 帮我看下这段代码哪里有问题 | （无） |

中文（含无钟点的「周五前」「下周三」截止语义）全部命中，凭据/代码/闲聊全不命中。零网络、零积分。

### 2.2 隐私标记可在不读正文的前提下看到

`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType`（[nspasteboard.org](https://nspasteboard.org/) 约定，
1Password、Bitwarden、TextExpander、Keyboard Maestro 等会写）。实测模拟密码管理器写入后，
`pb.types` 直接列出该标记，无需读正文。`changeCount` 同样免权限可读。

### 2.3 Electron 看不到这些标记 —— 决定了架构

实测 Electron 的 `clipboard.availableFormats()` 在带 ConcealedType 的剪贴板上**只返回 `["text/plain"]`**；
`clipboard.read('org.nspasteboard.ConcealedType')` 返回空串，**与「标记不存在」无法区分**（标记按约定就是空值）。

**后果**：主进程侧无法复核隐私标记。若按「helper 判定 → 主进程读正文」拆分，两步之间存在毫秒级窗口——
用户此刻若复制了密码，就会**绕过隐私标记这道门**。密码管理器复制后紧跟切窗口是常见操作，这不是理论风险。

**结论**：①②③④ 全部收进原生 helper，用 `changeCount` 前后夹紧，保证「检查标记」和「读正文」针对同一份内容。

### 2.4 macOS 26 的粘贴板管制尚未默认开启

`accessBehavior` 实测为 `.alwaysAllow`，`EnablePasteboardPrivacyDeveloperPreview` 未设置，多次读正文无弹窗。
即当前不是阻塞项；但苹果方向明确（读正文将按 App 弹授权），本设计天然把读取次数压到极低，属提前对齐。

## 3. 四道门

```
① changeCount 变了？                       免权限整数读取，800ms 轮询
      ↓
② types 含 Concealed/Transient/AutoGenerated？  → 跳过，不读正文
      ↓  不含 public.utf8-plain-text？            → 跳过（图片/文件留给 Alt+C）
      ↓
③ detectPatterns([CalendarEvent]) 命中？        不读正文、不触发系统提示
      ↓
── 以上全在 helper 内，changeCount 前后夹紧 ──
④ 读正文 → 再验 changeCount 与标记 → 经管道回主进程
      ↓
   主进程：排除名单 / 长度 / 冷却 / 限流 → 脱敏 → 上云 → 检测卡 + 桌宠气泡
```

启动时已在剪贴板里的内容不处理（否则每次开应用都拿旧内容弹一次）。

## 4. 模块

### 新建

| 文件 | 作用 |
|---|---|
| `src/shared/clip-gate.ts` | 省钱/降噪门纯函数 `decideClipboardParse` + `CLIP_LIMITS` |
| `src/main/clipwatch.ts` | ObjC helper 源码 + 常驻进程管理 + 命中后编排 |
| `test/clip-gate-smoke.mjs` | 门控单测 |

helper 复用 `native-helper-cache.ts` 的编译缓存与 `frontapp.ts` 的 clang 参数、长驻 + stdout JSON 行 + 退避重启模式。

### 修改

| 文件 | 改动 |
|---|---|
| `src/shared/types.ts` | `AppSettings` + `clipWatchEnabled`（默认 true） |
| `src/main/db.ts` | `getSettings` 读取该项 |
| `src/main/screenwatch.ts` | 抽出 `buildDetectionCards`；导出 `showDetectedCards` / `parsedToExtraction` / `cloudReady` / `DetectHit` |
| `src/main/index.ts` | 启动 `applyClipWatchSettings()`，退出 `stopClipWatch()` |
| `src/main/ipc.ts` | 存设置时跟随启停 |
| `src/renderer/src/pages/Settings.tsx` | 「剪贴板自动捕获」一节 |
| `package.json` | `test:clipgate` 并入 `test:unit` |

### 第四道门之后的降噪门（`clip-gate.ts`，纯函数、可单测）

| 门 | 值 | 理由 |
|---|---|---|
| 来源 App 排除 | 复用 `screenSenseExcludedApps` | 银行/密码类 App 即使没打标记也不碰；不新增设置项 |
| 长度下限 | 4 字 | 「明天」这种不可能是事项 |
| 长度上限 | 5000 字 | 整篇文档/代码 |
| 同内容冷却 | 10 分钟 | 与屏幕感知内容冷却同口径 |
| 全局限流 | 60 秒 | 连续复制时别把积分刷光 |

helper 另有 20000 字的硬上限，超过就不经管道回传（避免传输 MB 级正文）。

**冷却与限流只作用于自动路径**——Alt+C 是显式意图，无条件放行。

托盘暂停按 screenwatch 既定口径「用户暂停即全部暂停」，剪贴板一并停。

### 命中后复用现成链路

`redactSensitive` 脱敏 → `parseToItems` + `HINTS.clipboard_text` → `buildDetectionCards`（记入 detections、按强信号/清单模式挑卡）→ `showDetectedCards`（单条单卡、多条清单卡）→ `applyExternalPetSay`。

与屏幕路径的唯一口径差异：剪贴板路径**过滤掉 `belongs_to_user === 'no'`**。用户从群消息里复制到别人的安排很常见，全进记忆只会刷满历史；屏幕路径条目多、需要回看，故保留。

## 5. 降级与失败处理

- **macOS < 15.4**：helper 输出 `{"type":"unsupported"}` 并退出，主进程置 `unsupported` 标志并停止重启。**绝不退化成「直接轮询读正文」**——那会把这条链路的全部隐私优势丢掉。设置项说明系统要求。
- **helper 崩溃**：指数退避重启（2s 起，上限 60s），`ready` 事件复位计数。
- **detectPatterns 回调不返回**：helper 内 `busy` 标志超过 5 秒强制复位。这是唯一挡得住该失效模式的手段——进程仍活着，`exit` 监听和心跳都发现不了，所以不做心跳。
- **编译失败**（无 Command Line Tools）：`ensureNativeHelperBinary` 抛错 → 走重启退避 → 功能静默不可用，调试面板留痕。
- **解析失败**：仍然占用冷却与限流窗口，避免失败时反复重试烧积分。

## 6. 验证

**单测**（`test/clip-gate-smoke.mjs`）：排除名单优先级、长度上下限边界、冷却边界、限流边界、门的判定顺序。

**helper 真机实测**（已完成，macOS 26.5）：

```
中文日程        → hit      读到正文
中文截止        → hit      读到正文
普通闲聊        → skip nopattern   未读正文
API key         → skip nopattern   未读正文
代码片段        → skip nopattern   未读正文
英文日程        → hit      读到正文
ConcealedType   → skip concealed   未读正文
```

**待真机验证**：
1. 复制一条日程 → 桌宠气泡 + 检测卡在桌宠旁弹出，同意后进日程
2. 复制密码管理器里的密码 → 无任何反应（调试面板显示 `concealed`）
3. 连续复制多条日程 → 60 秒内只解析一次
4. 同一条内容复制两次 → 第二次不重复弹
5. 设置里关掉 → helper 进程消失（`pgrep clipboard-detect-v1` 为空）
6. 托盘暂停 → 复制日程无反应
7. Alt+C 手动捕获仍然可用，且不受冷却影响

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 命中即上云烧积分 | CalendarEvent 精度高；再加排除名单/长度/冷却/限流四道；实测闲聊与代码均不命中 |
| 800ms 轮询耗电 | 只读 `changeCount` 整数，未变即返回；detectPatterns 仅在内容变化时调用 |
| 苹果后续强制授权弹窗 | 架构已把读取次数压到最低；届时用户点一次「允许」即可，且 accessBehavior 按 App 记忆 |
| 来源 App 判定不准 | 优先用 `org.nspasteboard.source`，回退前台 App；仅用于排除名单，判错的后果是多解析一次 |
| helper 读正文后经管道回传 | 本地管道、父子进程、不落盘；正文本来就要到主进程 |
| 调试日志被刷爆 | `debugEvent` 无条件写盘，故 helper 的 skip 只在调试窗开着时上报；命中路径受限流保护，可正常记录 |
