# 记忆整理归纳验证（memory consolidation eval）

把模拟的「一天捕获流」（屏幕/剪贴板/通知/聊天片段 + 噪声）跑过**线上真实模型**整理成结构化「记忆」，验证算法（`src/shared/memory-consolidate.ts`）的聚类 / 摘要 / 待办抽取 / 去噪能力。思路参考 MineContext：批量消费原始 context → 去噪 + 按事件聚类 + 摘要 → 结构化记忆 + 抽待办。

## 跑

```bash
node eval/memory/run.mjs
```

自包含（esbuild 临时打包算法模块）；注册一次性账号、消耗 1 积分。清理：

```sql
delete from auth.users where email like 'eshell-val-%';
```

## 维度

| 维度 | 含义 |
|---|---|
| clusterCount | 记忆条数落在合理区间（事件级，非大类） |
| coverage | 每个主题领域（课程/求职/组会·报销/房租·快递）都被某条记忆覆盖 |
| threadGrouping | 真·多源同一事件线（课程项目=群通知+邮件+自记；求职=笔试+面试+公司资料）被并入一条记忆 |
| todoRecall | 应抽到的待办（项目/笔试/面试/报销/房租）都抽到 |
| todoTime | 待办时间解析正确（6/20、6/18、6/25） |
| noiseExclusion | 噪声（菜单/广告/闲聊/验证码）不进任何记忆的 source_refs |
| credential | 验证码/密码不出现在任何字段 |

## 基线结果（2026-06-15，模型 deepseek-v4-flash）

**7/7 维度通过。** 14 条捕获 → 6 条事件级记忆：课程项目（并 3 源，抽出「模块A 6/18」「项目提交 6/20」两待办）、求职复试（并 3 源，抽出笔试/面试）、组会、报销、房租、快递；菜单/广告/闲聊/验证码全部正确丢弃，凭据 482915 无泄漏。

> 设计说明：组会 vs 报销、房租 vs 快递是**独立单事件**，算法按事件级而非大类聚类（更利于每条记忆挂自己的待办），故 `threads` 只断言 course/job 两条真多源事件线的归并。
